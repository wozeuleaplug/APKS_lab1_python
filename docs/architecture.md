# Архітектура AI-Агента та Проєкту

## 1. Призначення та проблеми, які вирішує агент
 AI-агент (Build Engineer) створений для повної автоматизації рутинних завдань під час розробки кросплатформеного Python-проєкту. Він усуває ризики людських помилок при створенні структури каталогу, налаштуванні віртуального середовища (`venv`), написанні юніт-тестів та конфігурації CI/CD конвеєра.

## 2. Навички (Skills)
Агент використовує три основні модулі повторюваних інструкцій:
- **`project-scaffold`**: Відповідає за створення базової структури каталогу проєкту, файлу залежностей `requirements.txt`, оформлення `README.md` та початкового `.gitignore`.
- **`build-and-test`**: Описує процес генерації основного файлу програми (`main.py`) та модульного тесту (`test_app.py`) з використанням фреймворку `pytest`.
- **`github-actions`**: Налаштовує кросплатформений конвеєр через скрипти збірки (`ci.sh`, `ci.bat`) та файл `.github/workflows/ci.yml` для операційних систем Windows, Linux та macOS.

## 3. Команди користувача (Commands)
Користувачеві доступні такі іменовані операції:
- **`git-init`**: Перевіряє стан репозиторію Git, створює або оновлює `.gitignore` (ізолюючи тимчасові каталоги й `venv/`), виводить поточний статус.
- **`create-project`**: Викликає skill `project-scaffold` для ініціалізації структури.
- **`create-build`**: Викликає skill `build-and-test` для створення коду та тестів.
- **`create-actions`**: Викликає skill `github-actions` для генерації конфігурації CI.
- **`check`**: Виконує комплексну перевірку цілісності структури, конфігурацій, локальної збірки та проходження тестів, не змінюючи при цьому файли проєкту.

## 4. Передача даних між етапами
- На етапі ініціалізації фіксуються базові параметри репозиторію та правила ігнорування файлів.
- На етапі збірки генеруються залежності в `requirements.txt`, які потім автоматично використовуються локальними скриптами (`ci.sh` / `ci.bat`) для розгортання `venv` і запуску `pytest`.

## 5. Обробка помилок оркестратором (`init`)
Оркестраторна команда `init` послідовно запускає команди у такому порядку: `git-init` $\rightarrow$ `create-project` $\rightarrow$ `create-build` $\rightarrow$ `create-actions` $\rightarrow$ `check`.
Якщо на будь-якому кроці виникає збій (наприклад, помилка в тестах або відсутність обов'язкового файлу), оркестратор негайно припиняє виконання процесу, виводить детальний звіт про помилку та не дозволяє вважати збірку успішною.
